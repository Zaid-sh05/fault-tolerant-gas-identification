## 1. What was done

* **Data integrity and cleaning.** 9546 records in batches 1-7; the invalid-value rule (|x-median|/MAD > 1000, fitted on Train) removes 2 corrupt Train records and only counts evaluation ones (`cleaning/invalid_records_temporal.csv`). They had inflated the Train standard deviation of S06 |DR| by x316 (`../main_cleaned/diagnosis/std_s05_s08_before_after.csv`); the old SVM Macro-F1 of 0.878 was inflated by 0.022 (`../main_cleaned/diagnosis/design_2x2.csv`).
* **Phase 1, reconstruction of a sensor block**: Ridge in slog space is best; see section 3 (`phase1/protocol_comparison_summary.csv`). The mean and median fill-ins are worse than predicting the evaluation mean for all 16 sensors.
* **Phase 2, outliers (IQR)**: kept (winsorising SVM Macro-F1 0.8351 vs 0.8563); clipping does not hide a Bias fault (`phase2/bias_hiding_summary.csv`). Outliers are drift, not noise (`phase2/outlier_summary.json`).
* **Phase 3, scaling**: MinMax looked best (0.8841) but the stress check showed the gain comes from squeezing 11 features with extreme values (percentile-bounded MinMax gain -0.0035); StandardScaler is kept (`phase3/stress_*.csv`, `phase3/stress_check.json`). LightGBM varies by 0.028 across scalers, so it is not exactly scale-invariant in practice.
* **Phase 4, engineered features**: two sensor-local groups were tried; both lower SVM Macro-F1 (`phase4/candidates_val.csv`). The array-normalisation groups were rejected by P4 because they depend on all 16 sensors.
* **Phase 5, drift filter**: excluding the most drift-sensitive 10%/20% lowers SVM Macro-F1 (0.8420/0.8437 vs 0.8563) (`phase5/drift_options_val.csv`).
* **Decision rule** (gain > 0.005 and bootstrap interval excludes 0): 0 of 5 candidates adopted (`phase45/decision_rule.csv`). **The final preprocessing is the Baseline: StandardScaler on the 128 raw features, after the data cleaning rule.**

## 4. Final pipeline and rationale

`raw 128 features -> StandardScaler (fitted on cleaned Train) -> NaN->0 for the SVM` (LightGBM takes NaN natively), preceded by the data cleaning rule on the Train rows.

* **Cleaning rule**: corrupt records change the scaler statistics by orders of magnitude (see `DATA_CLEANING_RULE.md`).
* **StandardScaler**: the MinMax advantage disappears when the squeezing of 11 features is removed (`phase3/stress_check.json`).
* **No clipping, no engineered features, no drift filter**: none passed the pre-registered rule (`phase45/decision_rule.csv`).
* **Provenance**: all 128 columns are single-sensor blocks (`final/feature_provenance.csv`).

The official UCI feature definition of |DR| is ambiguous and the formulas of DR/|DR| were not found in any source reached; no feature relies on them.

## 5. Not done, and why

* Mode imputation: not applicable, all 128 features are continuous.
* Mutual information / ANOVA-F ranking and the |r| > 0.95 redundancy filter: dropped to save time (agreed shortened Phase 5).
* Cross-sensor-type ratios: the index-to-type mapping (TGS2600/2602/2610/2620) is not documented, only four of each type are known.
* Twin difference as a classification feature: it would let the classifier see a replica disagreement, i.e. the fault itself, and blur the separation between detection and classification; it is left to the reliability module.
* Array normalisation (pn_l2, pn_logmed): best single group for LightGBM (pn_l2: see `phase4/candidates_val.csv`) but a fault in one sensor changes the features of all 16 sensors, so P4 rejects it.
* Deleting statistical outliers from Validation: never done; Train rows are dropped only by the invalid-value rule.

## 7. Data cleaning rule

# Data cleaning rule

## Two kinds of extreme values
| kind | what it is | decision |
|---|---|---|
| statistical outliers (Tukey IQR fences) | real drift and strong responses; 83 of the 128 features show a batch-drift pattern and the outliers occur in bursts (dispersion index 19.7 in Train) | **kept** (Phase 2: winsorising lowers SVM Macro-F1 by 0.021, dropping the 587 rows with >10% outlying features gains only 0.004 < 0.005) |
| physically invalid values | corrupt records, e.g. `|DR|` = 31,165 where the median is about 2.6 | **removed from Train only**, by the rule below |

## Rule (fixed, `src/cleaning.py`)
* For every feature, median and MAD (median absolute deviation, unscaled) are computed on the **Train rows of the protocol only**.
* A cell is invalid if `|x - median| / MAD > 1000`; a record is invalid if any of its 128 cells is.
* Features with MAD = 0 cannot be scored (none occur).
* Train: flagged records are dropped before anything is fitted (scalers, imputers, selectors, models, fault scales).
* Evaluation rows (Validation, reference hold-out, later Test): **never dropped**, only counted, because a corrupt record in operation is a real fault the system must survive. They stay in classification scoring. They are left out of the reconstruction errors only, since their "true" value is itself corrupt.
* The threshold was fixed before looking at its effect and was not tuned.

## Effect on the Train statistics and on the old baseline
Standard deviation of the Train features before / after dropping the two records: `S06 |DR|` x316, `S08 |DR|` x48, `S07 |DR|` x25, `S05 |DR|` x3.7, `S04 EMAi0.1` x3.0, `S01 |DR|` x2.3, `S05 EMAi0.1` x1.6 (all other features unchanged).
StandardScaler therefore compressed these features by accident. A 2x2 design (C=10, gamma=scale) isolates the cause: SVM fitted on the cleaned rows but scaled with the old statistics gives 0.8764; scaled with the cleaned statistics 0.8563. The two records as training samples are irrelevant (-0.002); the whole change comes from the scaler statistics. The previously reported SVM Macro-F1 of **0.878 was inflated by 0.022** by two corrupt Train records that, through the inflated standard deviation, down-weighted drift-sensitive features by chance. Per-gas SVM F1 change: Acetaldehyde -0.048, Toluene -0.038, Acetone -0.025, Ethanol -0.010, Ethylene -0.008, Ammonia +0.015.
